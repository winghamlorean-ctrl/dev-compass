# Dev Compass（解题指南针）

人是指南针，AI 是加速器。

一个面向 AI 辅助工程的解题 Skill：先分清事实、推断与未知，提出可证伪的竞争假设，再围绕一个因果机制完成修复与验证。

不绑定具体业务或技术栈。换项目只认问题类型与问法，不照搬旧产品的功能名。

## 核心原则

- **先证实再改**：现象不等于根因，先查输入与执行路径。
- **一次一面**：一次处理一个因果机制，可以为它协调修改多个文件、模块或服务。
- **验收拆开**：覆盖合法主路径、复现与拒绝路径、数值边界、失败恢复和状态不变量。
- **默认关有边界**：只适用于可选、可降级能力，不适用于核心履约、安全、授权等契约。
- **人决定方向**：目标、硬约束、不做清单与验收标准需要明确。

## 适用场景

- 多入口、队列、定时任务或跨服务协作引发的问题。
- 局部测试通过，端到端业务仍失败。
- 指标好看，但用户实际体验没有改善。
- AI 根据症状直接改代码、不断叠规则，或缺少验证就宣称修复。

## 安装

### Cursor（原版安装方式）

下载或克隆仓库，将包含 `SKILL.md` 的整个目录放到：

```text
%USERPROFILE%\.cursor\skills\dev-compass\
```

确认 `SKILL.md` 直接位于该目录下，配套 Markdown 文件与它同级，然后重开 Cursor。

这是原 Skill 提供的安装方式；本次发布整理未进行客户端实测。其他工具的安装与自动触发兼容性尚未验证。

## 用法

在支持该 Skill 的工具中明确提出：「用 **dev-compass**」「先证实再改，一次一面」或「按解题内核」。

例如：

```text
用 dev-compass 调查这个重复通知问题。
先不要改代码，区分事实、推断与未知，提出可证伪的竞争假设。
确认根因后，只修一个因果机制，并按验收矩阵交付。
```

更多可复制提示见 [prompts.md](prompts.md)，完整规则以 [SKILL.md](SKILL.md) 为准。

## 反馈与贡献

欢迎通过 Issue 提供实际使用场景、预期行为与实际结果，或通过 Pull Request 提交聚焦的改进。

修改核心规则时，请说明要解决的具体问题，保留「一个因果机制可改多处」「默认关不适用于核心契约」与完整验收矩阵的适用边界。
